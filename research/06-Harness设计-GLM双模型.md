# Harness 设计建议（GLM-5.3 / GLM-5.3-Flash 双模型）

> 2026-09-21 ｜ 定位决策：**最终产物 = 记忆 harness**（记忆中间层 + 上下文装配 + 生成门控），主要搭配 GLM-5.3 与 GLM-5.3-Flash。
>
> **⚠️ 2026-09-22 修订（据学生手册，见 research/07）**：① 评测为 Oracle 档，本文 §1"打赢 full-context"的价值主张作废——**手册明令禁止全量拼上下文**（投机实现判 0 分），双模型分工保留但理由改为"写入质量与仲裁分级"；② 新增必做缺口：遗忘/生命周期策略、Episodic 原文层、检索效率数据（B.1/B.2）；③ 成本估算只需覆盖 Oracle 档（haystack 小，成本大幅下降）。架构本身（七模块）继续有效。

## 0. 模型前提（据公开资料，实现前需以官方文档/实测为准）

| 项 | GLM-5.3-Flash | GLM-5.3 |
|---|---|---|
| 定位 | 快/便宜档，GLM-5 系首个原生多模态 | 旗舰，强推理 |
| 架构 | 320B 总参 / 18B 激活（MoE，混合注意力） | GLM-5 基座 744B / 40B 激活一系 |
| 上下文 | ~1M tokens（第三方称 1,048,576，OpenRouter 列 1,310,720） | ~1M tokens，最大 128K 输出 |
| 能力 | function calling、结构化输出、tool use | 同左 + 更强长程推理 |
| 权重 | MIT 开放（HF: zai-org/GLM-5.3-Flash） | 开放权重 |
| API | OpenAI 兼容；`enable_thinking` / `reasoning_content`；有信息称 Flash 思考模式常开（**需实测**） | 同左 |

> 动作项：写一个 `probe_models.py`，实测两档模型的（a）真实可用上下文窗口（b）长文本各位置的召回退化曲线（c）thinking 开关行为与吞吐/价格——这三条直接决定下面的参数。

## 1. 1M 上下文窗口改变了设计前提

LongMemEval_S（~115K）与 M（~500K）**都能整段放进窗口**，因此：

- **full-context 基线是必须打赢的对手**，不再是"检索是唯一出路"——500 题 × 500K tokens 全量跑一遍要 ~2.5 亿输入 tokens，慢且贵，但技术上可行；
- harness 的价值主张改写为：
  1. **准确率 ≥ full-context**（长上下文存在 lost-in-the-middle、旧知识干扰更新、无证据硬答等系统性弱点，分题型可逐个击破）；
  2. **成本/延迟降 1–2 个数量级**（读取时只注入证据，不注入全部历史）;
  3. **知识更新 / 拒答 / 时间推理三类题型显著超越 full-context**——这是全上下文方法结构性吃亏的地方（过时信息就躺在上下文里，模型倾向于"看到就答"）；
- 设计红线：**任何检索式记忆模块上线前，先证明比同模型 full-context 强**，否则宁可退回 full-context。

## 2. 总体架构：七模块

```
                        ┌────────────────────────────────────────┐
 应用/评测 ──► ① 接口层 │ SDK: add_session()/answer()            │
                        │ OpenAI 兼容代理模式（可选）             │
                        └───────┬────────────────────────────────┘
              写入路径           │            读取路径
        ┌───────────────────────┴─────────────────────────────┐
        │ ② 写入管线 [Flash]    ─────────►  ④ 读取管线          │
        │  事实卡/画像卡/摘要树抽取         查询分析(题型/时间/实体)│
        │  冲突检测→失效/版本化(bi-temporal) 多路召回(BM25+dense+图)│
        │  幂等、增量、异步批量              rerank→证据打包(引用ID) │
        └──────────┬──────────────────────────────┬───────────┘
              ③ 存储层                     ⑤ 生成层 [Flash→5.3 路由]
        Qdrant(payload带时间/类型)      结构化输出 {answer,citations,confidence}
        BM25 索引；可选 Neo4j/FalkorDB  ┌──────────────┐
        全条目: valid_from/valid_to/    │ ⑥ 门控层      │
               observed_at+来源引用     │ 覆盖率门控拒答 │
                                       │ 可选 CoVe 自检 │
                                       └──────┬───────┘
                    ⑦ 评测层：LongMemEval adapter、分题型指标、成本/延迟统计、消融开关
```

### ① 接口层
- 主门面 SDK：`harness.add_session(session, ts)`（写入）、`harness.answer(question, ts) -> {answer, citations, confidence, route}`（读取+生成）；
- 可选第二门面：OpenAI 兼容代理（`/chat/completions`），记忆对调用方透明——便于接到任意现有应用；
- 全部可调参数（模型路由策略、阈值、组件开关）集中到一个 config，**消融开关是一等公民**。

### ② 写入管线（Flash 主力）
- 每轮/每会话增量触发，异步批量执行；
- 产物四类，全部带 `valid_from / valid_to / observed_at`（双时间轴）+ 来源（session_id + turn 区间）：
  1. **事实卡**：主体-关系-客体 + 置信度；
  2. **用户画像卡**：偏好/属性的结构化 profile（对齐单会话-用户/偏好题型）；
  3. **会话摘要**：近期保原文轮级索引，远期递归摘要树；
  4. **冲突失效记录**：新事实与旧事实矛盾 → 旧卡 `valid_to=now` 保留历史版本（支撑时间推理），物理不删除；
- 冲突判定是关键决策点：Flash 判"无冲突/明确冲突"，**低置信冲突升级 GLM-5.3 仲裁**（双模型级联的第一个落点）；
- 幂等：同一会话重复写入不产生重复记忆（内容哈希去重）。

### ③ 存储层
- Qdrant：payload 存 `type / valid_from / valid_to / session_id / turn_range / confidence`，检索时用**时间过滤**（as-of 查询：只召回 question_date 时仍然有效的记忆——"知识更新"题型在此直接受益）；
- BM25 并行召回（专名、日期、精确串）；
- 图存储阶段 2 再引入（HippoRAG 式 PPR 对"多会话推理"题型）；
- 向量化模型用 bge-m3 或 GTE-Qwen2（与官方基线可比），**注意 embedding 与生成模型解耦，不必绑定 GLM**。

### ④ 读取管线（Flash 主力）
1. **查询分析**（Flash，结构化输出）：题型预分类（信息抽取/多会话/时间/更新/拒答相关）、时间表达式解析、实体与关键词抽取 → 生成子查询；
2. **多路召回**：dense + BM25 + 画像直取（"我喜欢什么"类问题直接查画像卡）+（可选）图扩展；
3. **rerank**：先 embedding 分数粗排，Flash 轻量交叉重排 top-20；
4. **证据覆盖率评估**（Flash）：证据是否足以回答？输出 `coverage ∈ [0,1]` 与缺口描述；
5. **上下文组装**：证据按会话分组、带 `[cite:N]` 标签 + 相对/绝对时间戳；画像卡置顶。

### ⑤ 生成层（双模型路由）
- 结构化输出：`{"answer": str, "citations": [int], "confidence": float, "abstained": bool}`；
- 路由策略（config 可选，默认级联）：
  - `flash_only`：全 Flash，最省；
  - `cascade`（默认）：Flash 先答 + 自评置信度 → 低于阈值或题型=多会话推理/复杂时间 → 升级 5.3 重答；
  - `flagship_only`：全 5.3，上限参考；
  - `by_type`：按查询分析出的题型静态路由（评测用，行为可解释）；
- 系统提示三原则：**必须引用证据编号；证据不足时显式弃权（abstained=true）；时间问题必须基于证据时间戳推算**。

### ⑥ 门控层（反幻觉出口）
- 拒答条件（满足其一）：`coverage < τ1` 或 生成 `confidence < τ2` 且证据为空 → 输出标准拒答话术；
- τ1/τ2 在 S 版开发集上按 `_abs` 30 题 + 人工负样本调参（监控两个方向：该拒未拒 / 不该拒误拒）；
- 可选 CoVe 自检：Flash 对答案逐条拟验证问题 → 核对证据 → 修订；只在"高置信但影响大"的回答启用（成本考虑）。

### ⑦ 评测层
- LongMemEval adapter：读 haystack → 逐会话喂写入管线 → 逐题走读取管线 → 输出官方 JSONL；
- **对外报告的 judge 用官方协议（GPT-4o judge）保证可比**；开发期可加 GLM-5.3 第二 judge 交叉验证一致性（抽 ~100 题人工核对分歧）；
- 指标：分题型准确率、turn 级召回、引用命中率（citations 与 answer_session_ids 对齐率）、tokens 成本、写入吞吐、读取延迟 p50/p95、拒答混淆矩阵；
- 每次实验自动落盘 config + 结果，保证可复现。

## 3. 双模型分工总表

| 任务 | 模型 | 理由 |
|---|---|---|
| 事实/画像/摘要抽取 | Flash | 海量短任务，结构化输出，成本敏感 |
| 冲突检测（低置信仲裁） | Flash → 5.3 | 级联：拿不准才升级 |
| 查询分析/改写/子查询 | Flash | 快，允许失败回退 |
| rerank | Flash | top-20 交叉，成本低 |
| 答案生成（默认） | Flash | 基线档 |
| 多会话推理 / 复杂时间 / 更新冲突消解生成 | 5.3 | 多跳聚合是 Flash 短板 |
| 级联兜底 | 5.3 | Flash 自评低置信时 |
| CoVe 自检 | Flash（核对）/ 5.3（终审，可选） | 分层验证 |
| 开发期第二 judge | 5.3 | 与官方 GPT-4o judge 一致性需先校准 |
| 评测正式 judge | GPT-4o（官方协议） | 可比性红线 |

**Thinking 策略**：写入/分析类任务关思考或限最短输出（若 Flash 真的常开思考，用输出 schema + max_tokens 控制成本）；生成复杂题型时开启。写入管线的吞吐瓶颈在抽取调用数——按会话批量抽取而非逐轮，M 版 500 会话要控制并发与重试。

## 4. 成本模型（先估算，后实测）

- 写入：`C_write ≈ N_sessions × (抽取调用数/会话) × 平均输入tokens × Flash价`；M 版一次性建库是主要成本，但**建库成果跨题复用**（同 haystack 的多题共享记忆库——LongMemEval 每题 haystack 不同，需按 haystack 哈希分组复用，实测确认重复率）；
- 读取：`C_read ≈ 500 × (召回嵌入 + rerank + 生成 tokens)`；级联比例 p 升级 5.3 → 线性放大；
- 对照组：full-context M 版 ≈ 500 × 500K 输入 tokens（5.3 价），这是 harness 成本优势的分母。

## 5. 里程碑对齐（对 05 文档的修订）

- **阶段 0**：基线生成器换 GLM（注明与官方 GPT 数字不可直接比）；**新增必跑对手：GLM-5.3 full-context（S 与 M 都做）**；同时搭 harness 骨架（评测 harness 先行——复现三系统也要统一驱动）；
- **阶段 1**：复现 Mem0/Graphiti/Letta 时统一挂 GLM 底座模型，公平对比；
- **阶段 2**：本设计的写入/读取/门控逐模块实现，每模块一个消融开关；
- **阶段 3**：M 版冲刺，成本-准确率帕累托曲线（x=成本，y=分题型准确率）作为主图。

## 6. 风险清单

1. **模型规格未经官方确认**（1M 窗口、Flash 思考常开、价格）→ `probe_models.py` 先行；
2. **Flash 抽取质量不足** → 5% 抽样用 5.3 校验 + schema 校验失败重试 + 低置信条目标脏待升级重抽；
3. **judge 校准**：GLM-5.3 judge 与 GPT-4o judge 分歧率若 >5%，对外报告只用官方 judge；
4. **full-context 太强**：若 5.3 在 M 版 full-context 已 ≥ 预期目标，则 harness 卖点转向成本/延迟与"更新/拒答/时间"三类题型（这两条不受影响，仍然成立）；
5. **拒答误伤**：门控过严会拖累非 abstention 题型，τ 的消融必须做。
