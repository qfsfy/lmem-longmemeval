# 架构调研心得体会

> 调研对象：mem0（源码级）、Graphiti、Letta、MemOS、A-MEM、HippoRAG ｜ 2026-09-22

## 1. mem0 的本质：一条"蒸馏—存储—检索"流水线

- 它不是存对话原文，而是**写入时用 LLM 把对话蒸馏成独立事实句**，这才是记忆质量的源头。
- spaCy 小模型只是检索打分的配角（抽实体、做词形还原），可选项，记忆生成本身全靠 LLM。
- 读取时 mem0 **不自动注入**——默认是应用自己调 `search()` 再拼进 prompt；只有它的 OpenAI 封装才自动注入。
- 一句话定位：主动蒸馏写入、混合检索读出的**记忆中间件**，不是"带匹配算法的数据库"。

## 2. 检索：三信号融合，但权重是最浅的旋钮

- 三路信号：**语义**（抗释义）+ **BM25**（抓专名精确命中）+ **实体加成**（关联记忆加分，带"超级实体"折扣）。
- 语义分先做阈值门控再融合，防止关键词"后门"放进不相关记忆。
- 权重公式 `(semantic + bm25 + entity_boost) / max_possible` 很简单，**调它属于最后 5% 的收益**。

## 3. 优化空间在整条流水线，不在权重

- 真正的杠杆排序：**查询理解与改写 > 检索策略路由 > 写入侧策略 > 训练微调 > 权重精调**。
- 写入侧四个决策（粒度、冲突、时间、遗忘）决定天花板——没存对、没存下的记忆，检索怎么调都救不回。
- mem0 V3 自己的五项创新里四项都是写入/结构层面的，不是检索权重。

## 4. "用提示词实现" ≠ "本质是提示词工程"

- mem0 把冲突、去重、时间固化全写进提示词，是它的**产品哲学**（零训练、任意模型可插拔），不是唯一解。
- 每个写入决策都有结构化替代：约束解码强 schema、双时间轴边失效、专用时间解析器、算法化遗忘策略。
- 提示词政策的固有缺陷：**不确定、不可回归测试**——替换它就是创新空间。

## 5. 六仓库对比：三个共识 + 一个定律

共识：
1. **写入端全用 LLM 提取**，分歧只在表示形态（自由文本事实 / 三元组边 / 笔记卡片 / 自由块）；
2. **没人停留在平铺向量库**，都在加图结构——把检索问题部分转化为图遍历问题；
3. LLM 在读路径上只当"过滤器/重排器"。

定律：**记忆结构化程度与 agent 自治度大体负相关**——Graphiti 用强 schema 换算法化裁决，Letta 用弱结构换 agent 灵活性。

## 6. 冲突处理三阵营（LongMemEval 知识更新题的关键）

| 阵营 | 代表 | 做法 | 风险 |
|---|---|---|---|
| 不裁决 | mem0 V3 | ADD-only + 链接，读取时再裁决 | 库内长期并存矛盾事实 |
| 算法失效 | Graphiti | 双时间轴 + 边失效，**不改写不删除** | 图谱构建重 |
| 改写 | A-MEM / Letta | 新记忆触发旧记忆演化/编辑 | 历史信息丢失 |

结论：**失效不改写（Graphiti 路线）最稳**——可按时间窗取"当时为真"或"现为真"，历史无损。

## 7. 对项目的行动清单

1. **复现三极点**：Mem0（流水线）/ Graphiti（时序图）/ Letta（agent 自治），架构假设差异最大，对比信息量最高；
2. **读路径加 HippoRAG 对照**：PPR 图扩散是"聚合式检索"（多会话推理题要全量收集而非 top-k）的最成熟实现；
3. **三个能力杠杆优先做**：时间固化+日期预过滤（时间推理）、实体图全量收集（多会话推理）、弃答阈值校准（abstention）；
4. **先建误差归因管线再优化**：错题分到"提取缺失 / 检索未命中 / 排序错误 / 生成错误"四桶，oracle 实验测生成上限——瓶颈在哪先搞清楚；
5. 微调优先级：**嵌入领域适配 > 重排器 > 提取器 LoRA**，通用"输入输出小模型"最不划算。
