# 技术路线与下一步

> 调研日期：2026-09-21 ｜ 从调研到自研系统的分阶段路线

## 总体判断

LongMemEval 证明：**记忆增强 ≠ 简单 RAG**。当前开源方案在"多会话推理 / 知识更新 / 拒答"三类题型上普遍薄弱，这正是本项目的发力点。建议走"**先复现、再融合、后自研**"路线。

## 阶段 0：跑通基线（1–2 周）

目标：建立可复现的评测底座，拿到自己的第一组数字。

1. `git clone https://github.com/xiaowu0162/LongMemEval`，按 README 配 conda 环境（Python 3.9）；
2. 用 `LongMemEval_S`（~115K tokens）做开发集；
3. 跑通三组官方基线并记录：
   - full-context（长上下文全量，设性能上限参考）；
   - flat-BM25 + GPT 生成（检索式下限）；
   - dense retrieval（GTE-Qwen2-7B 或 bge-m3）+ rerank；
4. 用 `evaluate_qa.py`（GPT-4o judge）评测，按 `question_type` 分组统计——**分题型报告，找出最弱项**；
5. 产出：`results/baseline_report.md` + 评测自动化脚本。

## 阶段 1：复现三大代表系统（2–4 周）

用统一 harness 对比三种架构假设（详见 02 文档选型要点）：

| 系统 | 复现要点 | 预期强弱项 |
|---|---|---|
| Mem0 | 抽取-更新流水线；换成同样底座模型避免不公平 | 知识更新较强；多跳推理弱 |
| Graphiti | 时序 KG；需部署 Neo4j/FalkorDB | 时间推理、知识更新强；拒答弱 |
| Letta | agent 自编辑记忆；token 消耗大 | 偏好记忆强；长历史成本高 |

- 可借助 `mem0ai/memory-benchmarks` 套件减少接入工作量；
- 记录各系统的 **token 成本 / 延迟 / 存储**，不只看准确率；
- 产出：三方对比报告 + 各自失败案例分析（尤其 `_abs` 拒答题的行为）。

## 阶段 2：自研混合记忆架构（1–2 月）

基于复现发现，设计分层混合架构（命名待定，如 H-Mem）：

```
会话流 ──► 写入管线
  ├─ 事实抽取（用户画像卡 / 事件卡，带时间戳与来源轮次引用）
  ├─ 冲突检测与失效（触发 UPDATE/DELETE，版本化，bi-temporal 双时间轴）
  └─ 会话摘要树（近期原文 + 远期递归摘要）
存储层：向量库（bge-m3）＋ BM25 ＋ 图（实体-关系，PPR 联想）
读取管线：查询改写（时间感知）→ 混合召回 → rerank → 证据打包
输出门控：证据覆盖率 < 阈值 → 拒答分支（对齐 _abs 题型）
```

- 每个设计决策对齐一类题型（见 04 文档的映射表），消融实验按题型归因；
- 目标：S 版本全面超过三家复现基线，M 版本成本可控。

## 阶段 3：M 版本冲刺 + 论文级实验

- LongMemEval_M（500K tokens）全量评测 + 成本优化（记忆压缩、分层读取）；
- 关注 LongMemEval-V2（2026/05 官宣，agentic-context memory）动态；
- 若做中文场景：用 `sample_haystack_and_timestamp.py` 自建中文历史，测试跨语言记忆。

## 工程栈建议（阶段 0 即确定）

| 组件 | 选型 | 理由 |
|---|---|---|
| 推理服务 | vLLM（OpenAI 兼容接口） | 官方基线默认支持 |
| 向量库 | Qdrant 或 FAISS | 轻量起步，Qdrant 支持元数据过滤（时间戳） |
| BM25 | rank_bm25（开发期）/ Elasticsearch（量产） | 官方 flat-BM25 基线对齐 |
| 图数据库 | Neo4j 或 FalkorDB | Graphiti 官方支持这两者 |
| Embedding | bge-m3 或 GTE-Qwen2 | 官方基线之一即 GTE-Qwen2-7B |
| 裁判模型 | GPT-4o | 与官方评测协议一致，保证可比性 |
| 语言 | Python 3.9+ | 官方仓库环境 |

## 风险与注意事项

1. **厂商数字不可信**：Mem0/Zep/Letta 互相质疑对方基准（如 Mem0 论文称 Zep 记忆占用 ~600K tokens/会话，Zep 不认可），一切以自己复现为准；
2. **评测成本**：judge + 500K tokens 历史，M 版本一次全量评测开销大，开发期锁 S 版本；
3. **judge 偏差**：GPT-4o 裁判对拒答题的判定标准要先人工校验一批（~50 题）；
4. **数据版本**：HuggingFace 2025/09 有清理版，评测报告务必注明数据版本号；
5. **许可证**：LongMemEval 为 MIT，可自由改造；Mem0/Letta/Graphiti 分别是 Apache-2.0 / Apache-2.0 / Apache-2.0，商用自研需再核对各仓库最新 LICENSE。
